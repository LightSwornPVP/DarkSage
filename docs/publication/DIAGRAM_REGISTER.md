## 1. Purpose

This register is Deliverable 3 of the visual-publication production batch (alongside [DSF-003](DARKSAGE_VISUAL_DESIGN_SYSTEM.md), Deliverable 1, and `docs/publication/templates/`, Deliverable 2). It gives each of DSF-001 §G's 19 diagrams a concrete, trackable production record — a planned Mermaid source-file path, a `docs/standards/DIAGRAM_STANDARD.md` diagram class, and an authoring status — so future diagram-authoring work has a single register to build against instead of re-deriving placement/labeling/accessibility requirements from DSF-001 §G each time.

**Non-goal:** This register does not author any diagram's actual Mermaid source. Per DSF-001 §H.3 and §316, diagram source files belong under `docs/assets/diagrams/`; this register only names, per DSF-001 §G row, the specific file that will eventually live there. It does not renumber, rename, reclassify, or reorder any of DSF-001 §G's 19 diagrams, and it does not invent a 20th diagram.

## 2. Diagram Standard Class (elaboration, not restatement)

The **Diagram Standard Class** column below assigns each diagram one of `docs/standards/DIAGRAM_STANDARD.md`'s ten supported diagram classes (System context, Component, Data flow, Sequence, State machine, Entity relationship, Trust boundary/security, AI pipeline, Risk flow, Deployment). DSF-001 §G does not itself assign a Diagram Standard class per diagram — this is production-level detail this register adds, the same way DSF-003 added production detail DSF-001 scoped but did not state numerically. A future diagram author may refine a given class assignment during actual authoring without that refinement constituting a DSF-001 §G change, provided the diagram's Purpose, Source Volumes, Authoritative Labels, Placement(s), Type, and Accessibility Text Requirement (§3 below) remain exactly as DSF-001 §G states them.

## 4. File Naming and Rendering

- Source files use kebab-case per `docs/standards/NAMING_AND_ID_STANDARD.md` §File Naming, prefixed `figure-NN-` matching the `#` column above and the DSF-001 §F "Figure N — Title" caption convention.
- Text source (Mermaid or equivalent, per `docs/standards/DIAGRAM_STANDARD.md`) belongs under `docs/assets/diagrams/` per DSF-001 §H.3 and §316. The eight HIGH4 priority diagrams (Figures 2, 3, 4, 5, 11, 16, 17, 19) were authored under `docs/publication/diagrams/source/` per the batch's explicit direction — see `docs/publication/diagrams/README.md`'s "Location note" for this open, non-blocking coordination point between the two locations. The remaining eleven diagrams' **Source Path** cells still point to their DSF-001-aligned planned location.
- **Rendered Path** is honest per-diagram: **Pending / Not Yet Rendered** for the eight authored sources (no Mermaid/Graphviz renderer was available in the authoring environment — none was installed, per instruction), and **Not Yet Rendered** for the eleven not-yet-authored diagrams. No row claims a rendered SVG/PNG/PDF that does not exist on disk.
- Every controlled diagram must carry an ID, title, version/source reference, legend when symbols are non-obvious, and explicit system/trust boundaries where relevant, per `docs/standards/DIAGRAM_STANDARD.md` §Rules — the Diagram Page template (`docs/publication/templates/10-Diagram.md`) implements this at the page-layout level.
